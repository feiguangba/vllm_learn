# 50 章审核清单 (REVIEW_CHECKLIST)

每个审核 agent 用此清单逐课审查,输出结构化报告(JSON 或 markdown 表格)。
目标是找出「代码 bug、假数据、维度不清、讲解不细、每行未注释」等真实问题。

## A. 代码正确性(最重要,优先找 bug)
- [ ] 每个 code cell 是否零 error 输出(若未执行,说明你需判断代码逻辑)
- [ ] 是否有「假数据」:比如两种对比方案代码几乎相同、结论与数字矛盾、负的时间/占比
- [ ] 变量是否被正确使用(作用域、重绑定、numpy/torch API 是否正确)
- [ ] shape 是否正确:张量维度的乘法/转置/matmul 是否符合注释描述
- [ ] 数学公式是否与代码一致(公式说 O(T²),代码算的是否真是 O(T²))

## B. 讲解质量(用户核心诉求)
- [ ] 是否由浅入深:直觉 → 定义+公式 → 逐行推演 → 数值验证 → 真实规模 → 工程关联
- [ ] 每一行可执行代码是否都有 inline 注释(说明"做什么/为什么/shape")
- [ ] 关键张量是否打印 shape + 标注每个维度含义
- [ ] 是否有「维度符号表」(B/H/S/D 之类)贯穿全课
- [ ] 是否引用真实论文/博客(不是空链接或编造 arXiv 号)

## C. 完整性
- [ ] 章节结构是否完整(封面/学习目标/小结/练习/延伸阅读)
- [ ] app 直跑入口是否保留(st_runtime.exists() + subprocess 或 %%writefile 同步)
- [ ] 文件是否与配套 app/gen 脚本一致

## 输出格式
对每一课输出:
```
## 课 XX · <文件名>
- 严重问题(必须修): <代码 bug / 假数据 / 结论错误, 给出具体 cell/行>
- 中等问题(应该修): <讲解不细 / 维度不清 / 每行未注释的地方, 给具体位置>
- 轻微问题(可选修): <格式 / 措辞>
- 亮点: <做得好的, 保持>
```

## 判定标准
- 严重问题: 会误导读者或产生错误数字(如 24 课的 submit_batch==submit_many 假数据、负数 launch)
- 中等问题: 用户点名的「每行注释」「维度清晰」「由浅入深」没做到位
- 轻微问题: 可改可不改

## 重要提示
- 只审查,不修改文件
- 可以读 ipynb 的源码(cell.source)判断,也可以临时执行验证(但别改原文件)
- 重点抽查每章最有代表性的课,但 50 课都要过一遍(哪怕快速)
- 诚实报告:如果某课确实好,就说好,不要为了找问题而编造
